Attached
Tick it only if this machine has an interface with an address on that segment — ip -br addr on the host lists them. ARP only works on segments you are actually on, and device identity keys on MAC address: across a router SPARK can ping a host but never learn its MAC, so those devices are identified by IP and look like new devices whenever DHCP moves them.
When in doubt, tick it. The two mistakes do not cost the same. Ticking it wrongly is harmless — the ARP table has no entries for addresses beyond the router, so the lookups come back empty, you get IP identity anyway, and the Devices page shows a no ARP pill telling you the flag disagrees with reality. Unticking it wrongly is the expensive one: SPARK skips the ARP read even though it would have worked, and throws away MAC identity you could have had.
Sweep
Whether this subnet is included when the scan runs. Untick it to keep a segment listed here for documentation without pinging it — useful for somewhere you are not allowed to scan, or a range you only want on record. Devices already discovered there stay in the inventory; they just stop being re-checked.
VLAN
Documentation only. Nothing in SPARK reads the tag — not the sweep, not device identity, not the scheduler. It labels the subnet here and shows as a column on the Devices page, so the inventory records which VLAN a thing sits on without your network having to care.

Switching a port off does not close what is on it
SPARK stops checking it, which is not the same as the service having stopped — so anything already discovered on that port stays listed at its last known state rather than being marked closed. Marking it closed on the strength of not having looked would be an invention, and a target already watching that port keeps running either way.
Why hours and not minutes
What a machine listens on changes when you deploy something, not minute to minute. And a firewalled port costs a full timeout rather than an instant refusal, so every scan has a floor on how long it can take — running one every few minutes would spend the day scanning.
What it does to your network
One TCP connection per port per device, opened and immediately closed. Nothing is sent. It will appear in the logs of anything that logs connection attempts, and an IDS watching your LAN will see it for what it is — worth knowing before you point this at a segment that is not yours to scan.
